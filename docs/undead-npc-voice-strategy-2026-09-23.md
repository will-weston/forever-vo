**Distinct undead NPC voices — research and recommended next steps**

Prepared September 23, 2026, for the local ForeverVO project.

**My recommendation is to build a cast of voices that already feel undead before adding effects, then give each NPC a permanent voice profile.** Keep the installed IndexTTS audio as the quality baseline. Use the dry B audition you liked as a Mordo candidate, test whether cloning preserves its character, and retain effects only when a matched comparison demonstrates an improvement.

The research supports a change in workflow more strongly than it supports switching every line to a new model. The useful approaches are native voice-set matching, individual character casting, reusable voice identities, pronunciation correction, and separate review of delivery. I found a real WoW implementation of TTS followed by learned voice conversion, which merits a small experiment. I did not find a verified Blizzard Forsaken processing recipe.

I inspected six repositories locally and checked primary model documentation and adjacent game-mod workflows. “Implemented” below means visible in the inspected source; it does not mean I ran its pipeline or established that its audio sounds better. These are architectural findings, not a listening benchmark.

Spoken Quests exposes a particularly relevant limitation: its shared audio filenames can force NPCs with different native voice variants to use one consensus voice. That is an explicit compatibility compromise in the source. Our generation and playback keys must preserve individual speakers if we want individually cast NPCs. A different random seed is not a substitute for a different speaker reference. [Shared-file handling](https://github.com/rusty-key/spoken-wow/blob/9fa0d8815ebd2cae2a6a175987329fd5e8c6ada8/pipelines/quests/tts_cli/flavors.py#L105)

Its performance work is also more specific than “add emotion”: it distinguishes narration from NPC speech, translates vocal stage directions into the target engine’s tags, and carries pronunciation information into generation. These are useful ideas, but the tag syntax is engine-specific. We should not paste ElevenLabs tags into IndexTTS dialogue. [Narration handling](https://github.com/rusty-key/spoken-wow/blob/9fa0d8815ebd2cae2a6a175987329fd5e8c6ada8/apps/web/src/lib/generation/narration.ts#L39); [generation and lexicon integration](https://github.com/rusty-key/spoken-wow/blob/9fa0d8815ebd2cae2a6a175987329fd5e8c6ada8/apps/web/src/lib/generation/regenerate.ts#L164)

Two adjacent projects reinforce the distinction between recognizable characters and natural speech. Mantella’s Fallout documentation describes character histories and multiple speech backends, and explicitly reports that XTTS can sound natural for humans while struggling with robots/mutants or accents. That is the project’s assessment, not a controlled benchmark. xVASynth’s author/community guide emphasizes pronunciation dictionaries and editing pitch, duration, and individual troublesome sounds to improve a performance. Both suggest evaluating character fit and delivery separately. [Mantella documentation](https://art-from-the-machine.github.io/Mantella/pages/installation_fallout4.html); [xVASynth production guide](https://github.com/DanRuta/xvasynth-community-guide)

**Why our latest processing is a poor default**

The latest B treatment combined a low-mid EQ cut, a presence boost, a copy detuned by −35 cents and delayed 20 ms, and a synthetic dark tail mixed at 20% RMS. It did not add a compressor or limiter. That does not make it transparent: several audible changes were applied together, and any could make the voice less convincing. The source and effect settings are recorded in the [audition provenance](C:/repos/forever-vo/tools/samples/breathy-b-undead-audition/post-provenance.json).

My likely explanation is that the duplicate changes the vocal texture while the tail creates distance or murk. That is a listening hypothesis, not a measured diagnosis. Clones made from stock game clips may already reproduce some recorded ambience, so additional effects could compound it. That possibility also needs a controlled comparison.

Our earlier measurements found persistent low-frequency sound and an apparent decay in selected original clips. They did **not** recover the original dry performance, a unique impulse response, or Blizzard’s effect settings. The chosen wet level, pre-delay, filters, and detuning were audition choices. Treating those measurements as a complete effect recipe gave the reconstruction more authority than it deserved. [Measurement report and limitations](C:/repos/forever-vo/docs/mordo-processing-measurements.md)

For comparison, carevass’s actual undead function uses SoX with `reverb 15 35 30 10 60 -3`. This is a community preset, not evidence of Blizzard’s chain. I would retain it as one possible comparison after casting succeeds, rather than adopt it by default. Its processing path also re-encodes an MP3; we should retain a lossless master and encode the game file once. [Effect implementation](https://github.com/carevass/wow-voiceover-tbc-wotlk/blob/39e0111711a39a44768c1c6acceaad52841cb647/wowvo_client/audio_effects.py#L122)

The practical response is to bypass the current chain for casting. A voice that lacks the right character when dry should return to voice selection. Effects can be evaluated later, one component at a time.

**The revised formula**

| Decision | Proposed rule |
| --- | --- |
| Identify the speaker | Assign a profile by actual NPC/character identity. Record the native greeting sound set as evidence; visual race and gender are fallbacks. |
| Cast the voice | Audition complete phrases from one coherent speaker, or a deliberately designed synthetic voice. Choose by listening. Keep “I am Forsaken” and “Victory for Sylvanas” with the approved Sarvis identity; spreading the same anchors across all men works against differentiation. |
| Lock the identity | Save the approved reference audio, transcript, hash, model revision, and generation settings. Reuse that identity for accept, progress, completion, and gossip. |
| Direct the line | Record the speaker’s intent toward the player, energy, pace, and ending. “Give an unpleasant routine instruction” can be quiet and matter-of-fact even when the words concern killing. |
| Finish and review | Preserve complete endings and natural pauses, apply modest level adjustment, and test any optional effect against the dry take. Promote only the selected take. |

Ten seconds should be a useful reference-length target, not a reason to splice unrelated actors or pad with unsuitable performances. Keep alternate emotion references separate from the identity reference. Repeatedly mixing angry barks into the speaker sample makes it harder to tell whether we changed the actor or the acting.

“Undead” should be a family resemblance with several dimensions: airiness, worn voicing, creak, resonance, articulation, and attitude. It need not mean the same amount of rasp, the same low pitch, or the same echo on everyone. These proposed casting directions are creative choices for auditioning, not claims about canonical performances:

| NPC | Starting direction | How to distinguish them |
| --- | --- | --- |
| **Undertaker Mordo** | Use approved dry B as the first candidate: breath-worn, papery, tired, with understated amusement. | Intimate delivery, less ceremonial weight, practical phrasing. Must still pass the undead-fit test. |
| **Shadow Priest Sarvis** | Preserve the approved iconic reference and clean continuous IndexTTS approach. | Firmer articulation and composed authority; our continuity anchor. |
| **Novice Elreth** | Preserve her existing female reference as the starting point. | A more immediate, conversational concern or distaste where her text supports it. |
| **Maximillion** | Audition a separate dry identity with a restrained, severe manner. | Different resonance and cadence from Sarvis; avoid using the same two anchors as his entire identity. |

For NPCs sharing a native greeting kit, the stock recordings alone cannot guarantee uniqueness. We will need additional designed identities within that family. Audition the cast side by side on the same neutral sentence to expose near-duplicates, then on each character’s own text to assess fit.

**Which model paths are worth testing**

The first local path is **Qwen VoiceDesign → approved reference → Qwen Base voice cloning**. Qwen explicitly documents this workflow for reusable characters. It fits B because B was generated with VoiceDesign. Re-running the design prompt for every quest would invite identity changes; retain the actual approved audio instead. The Base cloning API is distinct from the instruction-controlled CustomVoice API, so we should not assume that arbitrary designed clones inherit all of CustomVoice’s instruction controls. [Official Qwen workflow and model capabilities](https://github.com/QwenLM/Qwen3-TTS#voice-design-then-clone)

The second is **the same approved reference → IndexTTS 2.5**. It has already produced takes you liked, and its API separates the speaker reference from emotion references or emotion vectors. Keep the clean continuous renderer, start with no emotion override, and introduce restrained direction only if it improves the line. Using a Qwen-designed reference in IndexTTS is our proposed cross-model experiment; neither project’s documentation guarantees that it will retain all the breathiness. [Official IndexTTS controls](https://github.com/index-tts/index-tts#-python-api)

The more experimental path is **a well-performed source recording → learned voice conversion → a chosen NPC timbre**. It may help when cadence is good but character texture is missing. carevass demonstrates that architecture with RVC, but RVC’s own English documentation recommends at least roughly ten minutes of low-noise training speech. Our short greeting compilation is not equivalent to that dataset. [RVC guidance](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/README.en.md)

For a low-data conversion trial, **Seed-VC** is the more direct research candidate: its authors describe conversion with 1–30 seconds of target reference and no speaker-specific training. The original repository is archived, so treat it as an isolated experiment with setup risk. Test whether it retains the source’s timing and the target’s roughness; do not assume it preserves both. Using one universal undead conversion target for everyone would risk making the whole cast alike again. [Seed-VC documentation and repository status](https://github.com/Plachtaa/seed-vc)

ElevenLabs is an optional paid comparison because several relevant WoW pipelines use it. Their choice establishes feasibility, not superiority on these undead samples. Our immediate work can remain local.

**The next experiment should be small and decisive**

1. **Freeze the comparisons.** Keep the installed Mordo recording, the approved dry B file, and the clean Sarvis take. Make a listening copy of the same Mordo opening excerpt at comparable loudness. The current full installed line and the short B audition differ in length; comparing matching words will be more useful.
2. **Run a three-way Mordo casting test.** Generate the same opening using B cloned by Qwen Base, B cloned by IndexTTS, and Mordo’s own stock voice kit through the clean IndexTTS renderer. Keep the original dry B and installed excerpt beside them as controls. No effects on these three new candidates.
3. **Verify that the winner generalizes.** Use the chosen Mordo identity for two unseen passages. A single good eight-second sample does not establish a dependable quest voice. Check text, accent, roughness, and whether the ending resolves naturally.
4. **Test character separation and acting.** Use Mordo, Sarvis, and Elreth for a nine-clip pilot: one neutral instruction, one restrained negative or urgent passage, and one completion/reward passage per NPC. Use exact quest text where available; label any test-only text. Compare the voices together, then listen in game with normal ambience.
5. **Only then test finishing.** On one winning performance, compare dry, reverb-only, and duplicate-only versions at matched loudness. If dry wins, ship dry. Reserve voice conversion for a case with clearly good delivery but inadequate character texture.
6. **Expand one NPC at a time.** Regenerate that NPC’s affected stages and gossip together after the profile passes. Keep the prior take selectable until the replacement has been heard in game.

The five listening questions are: does this feel like a Forsaken NPC; is it distinct from its neighbors; does it remain the same person across passages; is the delivery believable; and are there distracting artifacts or truncated endings? Text checks and loudness measurements support this review, but neither measures character appeal. Anonymous A/B labels help avoid choosing a model by reputation.

**How this fits our current source**

This does not require replacing the addon. The existing [Index batch tool](C:/repos/forever-vo/tools/index_quest_batch.py:53) already supports explicit NPC voice overrides through extra references, and the [clean renderer](C:/repos/forever-vo/tools/clean_index_quest_performance.py:40) already accepts hashed speaker references. Those are the right starting points.

There are three concrete gaps to address after the pilot:

- **One shared voice registry.** Give explicit character IDs priority over the current display-based sample lookup and race/gender fallback in [voice selection](C:/repos/forever-vo/tools/wowdata.py:132). A visual display ID is not necessarily a unique character. Store a stable profile ID, source kit, selected reference and hash, engine/model revision, transcript, pronunciation version, default delivery, and optional approved effects.
- **Correct regeneration decisions.** The batch tool’s current skip check compares engine name, voice label, and text, but not the reference hash or full profile version. Changing a reference behind the same voice name could leave stale recordings. Include a profile fingerprint in the generation cache and installed provenance. [Current skip logic](C:/repos/forever-vo/tools/index_quest_batch.py:74)
- **Speaker-aware audio identity.** Gossip filenames already include the speaker, while quest filenames are quest ID plus stage. Audit cases where different NPCs deliver the same stage before extending the project further. Preserve the correct speaker independently for accept, progress, and completion. [Current naming](C:/repos/forever-vo/tools/generate.py:83)

The first deliverable from that implementation should be a compact cast registry and audition manifest, not a full production website. Allvoice and Warcraft Quest Immersion provide useful patterns; our project only needs the parts that preserve identity, expose comparisons, and make rejected takes easy to replace.

The immediate priority order is **casting and stable identity → delivery → pronunciation and endings → optional effects**. Mordo is the best pilot because we have his own original voice kit, the installed baseline, a dry synthetic candidate you liked, and a processed version you find worse.
